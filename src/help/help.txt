# Topics

@@ BBC | COMPATIBILITY
BBC BASIC programs run: the BBC BASIC 3.10 language and the behaviour of the VDU, graphics, sound and file statements.

This is not a BBC Micro emulator. MODE 7's screen memory is at &7C00 as on the BBC, so programs that write teletext codes there work; the other modes keep their pictures elsewhere (see MODE and MEMORY). The BBC hardware at &FE00, the MOS internals and BBC machine code are not there: programs that poke the BBC's hardware, or CALL machine code written for the BBC, do not work.

The MOS calls a program can use are those in *HELP OSBYTE, *HELP OSWORD and *HELP MEMORY.

@@ KEYBOARD
Letters type in capitals, as with CAPS LOCK on a BBC Micro; Shift gives lower case. Shift+C= switches CAPS LOCK off and on again: off, letters type in lower case and Shift gives capitals (BASIC's keywords are capitals). OSBYTE &CA reads and sets it (bit 4 = 1: off), as on the BBC.

The ASCII characters the C64 keyboard lacks:

  \  pound key       ^  up-arrow
  _  left-arrow      |  Shift+pound
  ~  Shift+up-arrow  {  Shift++
  }  Shift+-         `  Shift+@

RUN/STOP is ESCAPE: it stops a program or a listing. RESTORE also sets ESCAPE.

Lines are typed with the MOS line editor (*EDIT), in every screen mode, up to 238 characters:

  LEFT, RIGHT     move in the line
  CLR/HOME        start of the line
  Shift+CLR/HOME  end of the line
  DEL, INST       delete, insert space
  UP, DOWN        earlier lines typed
  CTRL+cursor     move the copy cursor
  F1              COPY
  RETURN          enter the line

COPY editing as on a BBC Micro: CTRL with a cursor key starts a second cursor and moves it over the screen; F1 copies the character under it into the line and moves it on, so a listed line can be copied (in the text screens and MODE 7). UP and DOWN go through the last 127 lines typed at the prompt (kept in the REU). *EDIT C64 brings back the C64 screen editor (move the cursor anywhere and press RETURN; 78 characters after the prompt).

GET and INKEY return the cursor keys as 136-139 (left, right, down, up), DEL as 127 and CLR as 12.

@@ MEMORY
Memory map while BASIC runs:

  &0000-&0051  BASIC zero page
  &0052-&006F  MOS zero page
  &0070-&008F  free for machine code
  &0090-&00FF  C64 KERNAL
  &0100-&01FF  6502 stack
  &0200-&021F  BBC MOS vectors
  &02A7-&02FF  MOS error buffer
  &033C-&03FB  MOS variables
  &0400-&07FF  BASIC workspace
  &0800-&08FF  MOS command buffer
  &0900-&1CFF  sound engine
  &1D00-&7FFF  program (PAGE-HIMEM)
  &8000-&BFFF  BBC BASIC (RAM copy)
  &C000-&C3FF  screen / colours
  &C400-&C7FF  resident MOS
  &C800-&CFFF  VDU core
  &D000-&DFFF  I/O, graphics below
  &E000-&FFFF  KERNAL, bitmap below

PAGE is &1D00 (as on a BBC Micro with ADFS) and HIMEM &8000: 25.75K for programs. *SOUND NONE takes the sound engine out: a program may then set PAGE=&900 (31K). Some modes need RAM below HIMEM: MODE 7 keeps its screen at &7C00, the Upic Lite modes their picture at &5800 (MODE 4, 5, 6) or &3000 (MODE 1, 2); HIMEM is lowered to match, as on a BBC Micro. Under the I/O area is the drawing engine, under the KERNAL the bitmap (&E000) and the text font (&F000). The area &70-&8F is free for your own machine code, as on a BBC Micro.

BASIC runs from RAM because the Ultimate 64 reads cartridge ROM at 1 MHz even in turbo mode.

*MEMORY shows the map of the running program; *MEMORY UPIC OFF (or *SHADOW) keeps HIMEM at &8000 in every mode but MODE 7.

@@ FILES
Files are kept on the Ultimate's own storage: USB sticks (/Usb0, /Usb1), the SD card (/SD) and the RAM disk (/Temp, gone after power off). Names are Ultimate paths, relative to the current directory.

  *DIR /Usb0/bbc    choose a directory
  *CAT              list it
  SAVE "game"       save the program
  LOAD "game"       load it again
  CHAIN "game"      load and run

Two files can be open at the same time (channels &11 and &12): OPENIN, OPENOUT, OPENUP, BGET#, BPUT#, PRINT#, INPUT#, PTR#, EXT#, EOF#, CLOSE#.

Programs are saved in the BBC's tokenised format, so programs from BBC Micro disc images can be loaded once extracted to a file.

See also: *CAT, *DIR, *LOAD, *SAVE, *TYPE, *DELETE, *RENAME, *MKDIR.

@@ ULTIMATE
U64 BBC BASIC uses the Ultimate's command interface (UCI) for files, the clock and identification, and the U64 turbo registers for speed.

  *UVER    firmware targets
  *TIME    date and time
  *TURBO   CPU speed
  *CAT     files (see FILES)

The cartridge's .cfg file switches on everything needed when the cartridge is started from the Ultimate's file browser: Command Interface, REU, Ultimate Audio and the U64 turbo registers.

Planned: drives and disk images, REU, network, Ultimate Audio, Upic graphics, palette.

@@ ERRORS
An error stops the program and prints a message; ON ERROR catches it. ERR gives the error number, ERL the line, REPORT prints the message.

Errors from the Ultimate keep the Ultimate's text with these numbers:

  214  file not found
  189  access denied
  192  too many open files
  199  other Ultimate errors
  198  no room (LOAD too big)
  222  channel not open
  254  bad command
  252  bad number

@@ OPERATORS
Arithmetic: + - * / ^ (power), DIV and MOD (integers). Comparison: = <> < > <= >=, giving TRUE (-1) or FALSE (0). Logical/bitwise: AND OR EOR NOT.

Indirection reads and writes memory:

  ?A       byte at address A
  !A       4-byte integer at A
  $A       string at A (CR ended)
  A?2      byte at A+2
  A!4      integer at A+4

Example:

  DIM B% 10:?B%=65:PRINT ?B%

Hexadecimal: &FF is 255; PRINT ~X prints X in hexadecimal.

@@ VARIABLES
Names are letters, digits and _ and may be long. Types by suffix:

  A    real (5 bytes, ~9 digits)
  A%   integer (32 bits)
  A$   string (up to 255 chars)

The integers @% and A% to Z% are resident: they survive RUN, NEW and CLEAR. @% sets the PRINT format; A%, X%, Y% and C% pass registers to CALL and USR.

Arrays: DIM A(10), DIM N$(5,5). Strings keep their space when a new value fits. Space that strings give up is only reclaimed by CLEAR or RUN.

@@ ASSEMBLER
BBC BASIC contains a 6502 assembler. Square brackets enclose assembly language; P% is the address to assemble at; OPT sets listing and errors.

  10 DIM C% 20
  20 FOR Z%=0 TO 2 STEP 2
  30 P%=C%:[OPT Z%
  40 LDA #65:JSR &C7EE:RTS
  50 ]:NEXT
  60 CALL C%

OPT 0 assembles silently; OPT 2 reports errors; add 1 to list. Two passes resolve forward references. Labels start with a dot.

U64: OSWRCH is &C7EE, not &FFEE (see *HELP MOS). Zero page &70-&8F is free for your code.

@@ MOS
The MOS (machine operating system) entry points, at BBC Micro low bytes in page &C7:

  OSFIND &C7CE   OSGBPB &C7D1
  OSBPUT &C7D4   OSBGET &C7D7
  OSARGS &C7DA   OSFILE &C7DD
  OSRDCH &C7E0   OSASCI &C7E3
  OSNEWL &C7E7   OSWRCH &C7EE
  OSWORD &C7F1   OSBYTE &C7F4
  OSCLI  &C7F7

The RAM vectors are at &0200-&021F as on a BBC Micro (BRKV &0202, WRCHV &020E, ...). See OSBYTE, OSWORD and VDUCODES.

@@ OSBYTE
OSBYTE calls (*FX a,x,y) available:

  &00   OS version (X=1)
  &0F   flush keyboard buffer
  &15   flush keyboard buffer
  &72   shadow for next MODE
  &75   VDU status (4: shadow)
  &7C   clear ESCAPE
  &7D   set ESCAPE
  &7E   acknowledge ESCAPE
  &7F   EOF# of channel X
  &81   INKEY
  &82   high address (&FFFF)
  &83   OSHWM / PAGE (&1D00)
  &84   HIMEM of the mode
  &85   HIMEM for a mode
  &86   POS (X) and VPOS (Y)
  &87   character at cursor
  &04   cursor keys (kept)
  &0B   key repeat (0 off)
  &0C   key repeat (0 default)
  &13   wait for the frame's end
  &80   ADVAL
  &A3   GXR (accepted)
  &C8   bit 0: ESCAPE off
  &CA   keyboard status (CAPS LOCK)
  &DC   escape character
  &DA   VDU queue length
  &E5   ESCAPE key off (X<>0)

Other calls are ignored. Key repeat uses the KERNAL's speed: *FX 11,n and *FX 12,n with n > 0 make every key repeat. *FX 220,c makes the key typing ASCII c set ESCAPE (27: only RUN/STOP).

@@ OSWORD
OSWORD calls available: 0 reads a line (the line editor, *EDIT), 1 reads TIME, 2 sets TIME (5 bytes, centiseconds), 9 reads a pixel (POINT), 10 reads a character definition (block +0 = character; +1 to +8 = rows), 14 reads the Ultimate's clock, &42 copies between memory and the REU (block +0: &80 to the REU, 0 from it; +1/+2 address; +5/+6 length; +7 the REU's 64K bank (4-255); +8/+9 address in the bank; as the Master's sideways RAM transfer), &70 reads a value of the JSON reply *JSON GET keeps (see *JSON), &71 moves sprites (see *SPRITE). Others are ignored.

OSWORD 14 as on a BBC Master: put 0 in the first byte of a 25-byte block for the text "Wed,07 Oct 2026.08:42:55" and a CR, or 1 for 7 BCD bytes: year (2 digits), month, day, day of week (1 = Sunday), hour, minute, second.

  DIM B% 25:?B%=0:A%=14
  X%=B% MOD 256:Y%=B% DIV 256
  CALL &C7F1:PRINT $B%

@@ VDUCODES
VDU codes work as on a BBC Micro:

  4     text at the text cursor
  5     text at the graphics cursor
  7     bell (SOUND &13,-15,101,6)
  8-11  cursor left/right/down/up
  12    clear the text window (CLS)
  13    start of line
  16    clear the graphics window (CLG)
  17,n  COLOUR n
  18,a,n  GCOL a,n
  19,l,p,0,0,0  colour l shows colour p
  19,l,16,r,g,b  colour l as RGB
  20    default colours and palette
  22,n  MODE n
  23,1,n  cursor off (0) / on (1)
  23,11  default ECF patterns
  23,12-15  define ECF pattern 1-4
  23,c,8 rows  define character c
  24,l;b;r;t;  graphics window
  25,k,x;y;  PLOT k,x,y
  26    default windows
  28,l,b,r,t  text window
  29,x;y;  graphics origin
  30    cursor home
  31,x,y  TAB(x,y)
  127   delete

Windows, the graphics codes and the palette act in the graphics modes (MODE 1, 2, 4, 5, 103, 104); in text modes 12, 17 and 22 act.

VDU 23,c,r1,...,r8 (c = 32-255) defines a character: 8 rows, top first, bit 7 left. The text screen shows codes 32-127; graphics modes show all of them with an REU (the Ultimates; kept over MODE changes). MODE 7 keeps its teletext glyphs. OSWORD 10 reads a definition.
@@ COLOURS
COLOUR n sets the text colour, COLOUR 128+n the background. BBC colour numbers map to C64 colours:

  0 black    1 red      2 green
  3 yellow   4 blue     5 magenta
  6 cyan     7 white    8 orange
  9 brown    10 light red
  11 dark grey  12 grey
  13 light green  14 light blue
  15 light grey

@@ SPEED
On an Ultimate 64 or C64 Ultimate with the U64 turbo registers enabled, BBC BASIC starts at the highest speed of the machine: 48 MHz (Ultimate 64, Elite) or 64 MHz (Elite II, C64 Ultimate). That is 25 to 30 times a BBC Micro.

TIME stays in real time at every speed. *TURBO shows or changes the speed. On an Ultimate II+ or a plain C64 the speed is 1 MHz.

@@ LIMITS
Things that differ from a BBC Micro in this version:

Typed lines: 238 characters (78 with *EDIT C64); programs sent from a PC (see REMOTE) may have lines up to 251 characters. Graphics: points, lines, triangles, rectangles, parallelograms, circles, ellipses, pattern fills, flood fill, arcs, segments, sectors. Sound: SOUND and ENVELOPE as on a BBC Micro. LOAD and SAVE work between PAGE (&1D00, or &900 with *SOUND NONE) and &7FFF. Two files open at a time. *EXEC and *SPOOL are not there yet.

@@ REMOTE
Programs can be written on a PC and run here: the MOS has a mailbox that a PC (or an AI coding agent) reaches through the Ultimate's network API. At the > prompt the MOS accepts lines and programs from it as if typed, and copies the output back.

  tools/u64remote.py run prog.bas
  tools/u64remote.py exec "PRINT 6*7"

AI agents use the same through the MCP server tools/u64mcp.py. Nothing changes for the user at the keyboard. See docs/REMOTE_DEV.md and docs/AI_AGENTS.md.

@@ DEBUG
Programs sent from a PC can be debugged there: breakpoints, single steps and a view of the variables (VS Code: F5; command line: tools/u64remote.py debug; AI agents: bbc_debug).

It uses TRACE: BASIC reports each line before it runs and the MOS pauses at a breakpoint. The line after a FOR or REPEAT is reported only on the first pass (NEXT and UNTIL jump back into the loop line), so for later passes put the breakpoint on the NEXT or UNTIL line. See REMOTE.

# ---------------------------------------------------------------------------
# * commands

@@ *CAT | CAT | *.
  *CAT     (also *.)

Lists the current directory: the path, then the files in two columns. Directories end in /. ESCAPE stops the listing.

@@ *DIR | DIR | *CD | CD
  *DIR <path>     (also *CD)
  *DIR ~

Changes the current directory. Paths are Ultimate paths: /Usb0/bbc, /SD, /Temp, .. for the parent; ~ is the Ultimate's home directory (User Interface settings).

  *DIR /Temp
  *DIR ..

@@ *PWD | PWD
  *PWD

Prints the current directory.

@@ *MOUNT | MOUNT
  *MOUNT <image> [A|B|<device>]

Mounts a disk image (D64, D71, D81, G64 ...) on one of the Ultimate's drives, drive A if none is given.

  *MOUNT /USB0/games/elite.d64
  *MOUNT disk2.d64 B

@@ *UNMOUNT | UNMOUNT
  *UNMOUNT [A|B|<device>]

Removes the disk image from a drive (drive A if none is given).

@@ *SWAP | SWAP
  *SWAP [A|B|<device>]

Moves a drive (drive A if none is given) on to the next disk of its disk set, as the Ultimate's swap function does for multi-disk games.

@@ *DRIVE | DRIVE
  *DRIVE A|B ON|OFF

Switches one of the Ultimate's drives on or off.

@@ *COPY | COPY
  *COPY <file> <directory>

Copies a file into another directory on the Ultimate's storage, under the same name. An existing file there is not overwritten (error "File exists").

  *COPY game /USB0/backup

@@ *SETTIME | SETTIME
  *SETTIME yyyy/mm/dd hh:mm:ss

Sets the Ultimate's clock. The Ultimate's settings can forbid this (error "Function prohibited").

@@ *PARTITION | PARTITION
  *PARTITION <n> <path> [<name>]
  *PARTITION <n> OFF

Makes partition n of the Ultimate's SoftIEC drive point to a directory. From firmware 3.15 the SoftIEC drive reaches files only through partitions; without one it serves /Temp. OFF removes a partition (not effective on firmware 3.15a).

  *PARTITION 3 /USB0/c64 GAMES
  *CP 3

@@ *PARTITIONS | PARTITIONS
  *PARTITIONS

Lists the SoftIEC drive's partitions (its "$=P" directory).

@@ *CP | CP
  *CP <n>

Selects partition n on the SoftIEC drive (the drive's own CP command).

@@ *DELETE
  *DELETE <name>

Deletes a file.

@@ *MKDIR | MKDIR | *CDIR | CDIR
  *MKDIR <name>   (also *CDIR)

Creates a directory.

@@ *RENAME | RENAME
  *RENAME <old> <new>

Renames a file.

@@ *KEY | KEY
  *KEY n text     set function key n
  *KEY n          clear it
  *KEY            list the keys set

Function key Fn (1-8; F2, F4, F6, F8 are Shift with F1, F3, F5, F7) then types the text, at the prompt and in programs (GET, INKEY, INPUT), as on a BBC Micro. Codes in the text: |M RETURN, |A-|Z control codes, |? DELETE, || |, |" ", |! the next character + 128. Quotes around the text are optional.

  *KEY 2 LIST|M
  *KEY 3 "RUN|M"

F1 is the line editor's COPY until *KEY 1 is set. Up to 63 characters a key; keys 0 and 9 are kept (BBC programs set them) but have no key. The texts are kept in the REU. With *EDIT C64 the keys type nothing.

@@ *LIST
  *LIST           all
  *LIST n         line n
  *LIST n,        from line n
  *LIST ,m        up to line m
  *LIST n,m       lines n to m

Lists the program indented by its structure: two spaces per level of DEF PROC ... ENDPROC, a DEF FN that ends with a line starting "=", FOR ... NEXT and REPEAT ... UNTIL (LISTO 7 indents only the loops). The program itself is not changed; spaces at the start of its lines are replaced by the indentation. ESCAPE stops.

@@ *LOAD
  *LOAD <name> <address>

Loads a file into memory at an address (decimal or &hex), between &1D00 (&900 with *SOUND NONE) and &7FFF.

  *LOAD screen &3000

@@ *SAVE
  *SAVE <name> <start> <end>
  *SAVE <name> <start> +<length>

Saves memory to a file. The end address is not saved. Memory up to &7FFF can be saved.

  *SAVE code &3000 +&200

@@ *TYPE | TYPE
  *TYPE <name>

Prints a text file. Lines end in CR; LF and other control codes are skipped. ESCAPE stops.

@@ *SPOOL | SPOOL
  *SPOOL <name>   start
  *SPOOL          end

Copies everything printed into a file, as on a BBC Micro: *SPOOL name, then for example LIST, then *SPOOL alone. The output is collected in the REU's last 64K (up to 47K) and written to the file when the spool ends (also by CLOSE#0 or another *SPOOL), so it is fast and safe while the MOS prints during file operations. Needs an REU; the RAM disk ends below that last 64K.

  *SPOOL listing
  LIST
  *SPOOL

@@ *EXEC | EXEC
  *EXEC <name>

Reads the file as if it were typed: every byte becomes a key, at the prompt and in programs (GET, INKEY, INPUT), until the file ends; *EXEC alone or ESCAPE stops it. LF ends a line too (files from a PC). A program typed in as text can be loaded this way, or a list of commands run.

  *EXEC commands

@@ *BUILD | BUILD
  *BUILD <name>

Writes the lines you type into a file, each ended by CR, until ESCAPE. The line numbers shown are not written. Made for *EXEC files.

@@ *DUMP | DUMP
  *DUMP <name>

Shows a file in hexadecimal: the offset, 8 bytes and the same bytes as characters (. for control codes). ESCAPE stops.

@@ *INFO | INFO
  *INFO <name>

Shows a file as DFS does: name, L if locked, load and execution address, length (hexadecimal). Files on the Ultimate's drives have no addresses (0).

@@ *ACCESS | ACCESS
  *ACCESS <name> L   lock
  *ACCESS <name>     unlock

Locks a file on the RAM disk (/REU): a locked file cannot be deleted, replaced, renamed or opened for output ("Locked"). The Ultimate's drives have no lock: their files give an error.

@@ *RUN
  *RUN <name>

Loads machine code and calls it. A file with a load address (*SAVE on /REU) goes there and is called at its execution address. Otherwise the file is a C64 program file: its first two bytes are the load address, and it is called there. Only &0400-&7FFF.

@@ *SEARCH | SEARCH | *FIND | FIND | *REPLACE | REPLACE | TOOLKIT
  *SEARCH s1[,s2]   (asks Parameters)
  *FIND s1          list the lines
  *REPLACE s1,s2    replace, asking

Searches the program, as Beebug's Toolkit Plus: every line holding s1 is listed. With s2, each match may be replaced (Replace Y/N:). *SEARCH then asks for Parameters, letters typed together: C case ignored, D not in DATA, R not in REM, " not in strings, K s1 and s2 are keywords, G replace all without asking. # in s1 matches any character. Without K, keywords are not found (they are stored as tokens); line numbers after GOTO are never matched. A replacement clears the variables, as editing does.

  *FIND count
  *SEARCH PRINT,REPORT  (then K)

@@ *XREF | XREF | *VARLIST | VARLIST
  *XREF [R I S A F P H L]
  *VARLIST          (as *XREF L)

Lists the variables, arrays, procedures and functions with their values and the lines that use them, as Beebug's Toolkit Plus. Letters choose: R reals, I integers, S strings, A arrays, F functions, P procedures (none: all); H values in hexadecimal, L no line numbers. Only what the program has made so far is known: run it first. A% to Z% are listed when the program uses them. Values are printed as PRINT would (@%).

@@ *CRUNCH | CRUNCH | *PACK | PACK
  *CRUNCH [C R S :]   (also *PACK)

Makes the program shorter, as Beebug's Toolkit Plus: spaces, REM statements and extra colons go, and lines are joined. A letter switches that part off: C joining, R REMs, S spaces, : colons (B, L, T and V are accepted; brackets, LET, THEN and names are never changed). It asks first and prints the sizes; keep a copy. Lines named by GOTO, GOSUB or RESTORE keep their number (and their REM); lines are not joined after IF, ON, ELSE, DATA or a * command, nor are DEF and DATA lines joined on. Strings, DATA, * commands and assembler stay as they are. A computed GOTO's target is not known: use C there. Needs an REU.

@@ *SPEECH | SPEECH | *SAY | SAY | *SPEAK | SPEAK | SAM
  *SPEECH LOAD f [f]  your SAM files
  *SPEECH             what is loaded
  *SPEECH SPEED n     (also PITCH,
                       THROAT, MOUTH)
  *SAY text           English
  *SPEAK phonemes     SAM's spelling

Speech with S.A.M. (Software Automatic Mouth, Don't Ask Software 1982), which is not part of U64 BBC BASIC: load your own copy of the C64 package once, its ".sam 1" (SAM, loads at &9500) and ".sam 2" (Reciter, &7D00, for English), copied as files without spaces in their names; they are told apart by their load address and kept in the REU (its last 64K, with *SPOOL). *SAY speaks English through Reciter, *SPEAK SAM's phonemes (e.g. HEH4LOW). Defaults: speed 72 (bigger is slower), pitch 64 (smaller is higher), throat and mouth 128. The screen is blank while SAM speaks, at 1 MHz; the program then goes on. Up to 230 characters; a word without a vowel (BBC) is spelt out. Needs an REU.

  *SPEECH LOAD sam1.prg sam2.prg
  *SAY Hello, I am a BBC Micro.

@@ *UVER | UVER
  *UVER

Shows the identification of the Ultimate's DOS and control targets.

@@ *TIME
  *TIME

Prints the date and time of the Ultimate's clock. The BASIC variable TIME is a separate centisecond counter.

@@ *TURBO | TURBO
  *TURBO          show the speed index
  *TURBO MAX      fastest (index 15)
  *TURBO OFF      1 MHz (index 0)
  *TURBO <n>      speed index 0-15

Needs the U64 turbo registers (Turbo Control in the Ultimate's settings, switched on by the cartridge's .cfg). Index 15 is 48 MHz on an Ultimate 64 and 64 MHz on an Elite II or C64 Ultimate. See SPEED.

@@ *FONT | FONT
  *FONT LOAD <file> [fmt]  load
  *FONT SAVE <file> [fmt]  save
  *FONT BBC      BBC Micro characters
  *FONT C64      C64 character ROM
  *FONT DEFAULT  the start-up font
fmt: C64 (default), BBC or ASCII.

C64 is a C64 charset: 2048 bytes in screen-code order (2050 with a load address also loads). BBC is 768 bytes, characters 32-127 in ASCII order, as in a BBC Micro MOS ROM at &C000. ASCII is 2048 bytes, characters 0-255 in ASCII order.

With an REU (the Ultimates) the font shows on the text screen and in the graphics modes and stays over MODE changes. Without one only the text screen changes. MODE 7 builds its teletext glyphs from the font when it starts. VDU 23 changes single characters. The BBC characters are Acorn's (see CREDITS).

@@ *MEMORY
  *MEMORY            memory map
  *MEMORY UPIC OFF   VIC-II modes
  *MEMORY UPIC ON    Upic Lite
  *MEMORY UPIC AUTO  (as ON)

Shows PAGE, TOP, LOMEM, VARTOP, HIMEM, free memory and where the screen is.

On a 64 MHz Ultimate the BBC modes 0-6 use Upic Lite: exact 320x256 like a BBC Micro, with the picture below HIMEM (&5800 or &3000), as on the BBC. UPIC OFF makes the next MODE use the VIC-II version instead: 200 lines, but HIMEM stays &8000. The same as *SHADOW. MODE 7 always keeps its screen at &7C00.

@@ *EDIT | EDIT
  *EDIT BBC   the MOS line editor
  *EDIT C64   the C64 screen editor
  *EDIT       shows which one is used

BBC (the default): lines up to 238 characters in every screen mode, edited in place, with the last 127 lines on UP and DOWN and BBC copy editing (CTRL+cursor keys, F1 is COPY). See KEYBOARD.

C64: the KERNAL's full-screen editor in the text screen, as on a C64: move the cursor anywhere on the screen and press RETURN to enter that line; 78 characters after the prompt. In the graphics modes lines are typed without editing.

@@ *SNAPSHOT | SNAPSHOT
  *SNAPSHOT n          take (slot 1-9)
  *SNAPSHOT LOAD n     back to it
  *SNAPSHOT            list the slots
  *SNAPSHOT SAVE n f   slot to file f
  *SNAPSHOT LOAD f     from file f

A snapshot keeps BASIC's world in the REU: the program, its variables, BASIC's workspace and zero page (not &52-&6F), the screen mode, with the time it was taken. Taking and restoring take a moment. Take it at the prompt; LOAD brings the program and the variables back as they were (the screen's content is not kept). PAGE must be the same as when it was taken.

  *SNAPSHOT 1
  NEW
  *SNAPSHOT LOAD 1

Slots 1-9 lie at &B8000-&FFFFF (*SRWRITE and OSWORD &42 stop below &90000) and go when the power goes off; SAVE copies a slot to a file on the Ultimate's drives, LOAD with a name reads one back. Needs an REU of 1 MB or more.

@@ *SHADOW | SHADOW
  *SHADOW     shadow modes
  *SHADOW 1   normal modes

As on a BBC Master: from the next MODE on, a shadow mode keeps the screen out of BASIC's memory, so HIMEM stays &8000. Here that is the VIC-II version of the mode instead of Upic Lite. MODE 128+n is shadow for that mode only. OSBYTE &72 does the same from a program (X = 0 shadow, 1 normal), OSBYTE &75 bit 4 says whether the current mode is one. See *MEMORY.

@@ *JSON | JSON
  *JSON GET <url>   fetch and keep
  *JSON <path>      show a value

A JSON reply from a web address (plain http), read and kept by the Ultimate (firmware 3.15). Paths go down the reply with / and pick an array's element with %n (from 0):

  *JSON GET http://api.open-notify.org/
    iss-now.json
  *JSON iss_position/latitude
  *JSON %0/title

A string is shown as it is, a whole number in decimal, TRUE or FALSE; an object or array shows nothing (OSWORD &70 gives its count).

Programs use OSWORD &70 with a 9-byte block: +0/+1 the path's address, +2 its length, +3/+4 where the value goes, +5 the room there. Back: +6 the type (0 none, 1 number, 2 TRUE/FALSE, 3 string, 4 object, 5 array), +7 the value's length, +8 an object's or array's count. demos/net/JSONLIB has FNjson(path$), FNjsonnum(path$) and FNjsoncount(path$).

@@ *NET | NET | NETWORK
  *NET                  the address
  *NET GET <url> <file> download
  *NET TIME [server]    set the clock
  *NET RANDOM           seed RND

The Ultimate's network. *NET shows its IP address, netmask and gateway. *NET GET fetches a web address over plain http (not https: the Ultimate cannot do encryption) and saves what it returns in a file, also on the RAM disk; up to 16 KB (the Ultimate keeps no more of a reply). Needs firmware 3.15 and an REU.

  *NET GET http://example.com/ PAGE

*NET TIME has the Ultimate set its clock from a time server (its own SNTP client, in its time zone setting); the server is optional. *NET RANDOM seeds RND from the drand public randomness beacon, so a program gets a sequence nobody can predict.

Files on the network open as channels: OPENIN "http://..." reads a web reply like a file (BGET#, EOF#, EXT#), and OPENUP "TCP:host:port" or "UDP:host:port" opens a connection: BPUT# sends (a TCP line goes out at its CR or LF), BGET# waits for the next byte (ESCAPE stops it), EXT# is the number of bytes waiting, EOF# is TRUE when the other side has closed. PTR#c=0 sends what is waiting (a UDP datagram). At most two files and connections are open at a time.

@@ *PALETTE | PALETTE
  *PALETTE LOAD <file> [VPL]
  *PALETTE SAVE <file>
  *PALETTE BBC    BBC's pure colours
  *PALETTE C64    Ultimate's defaults
  *PALETTE RESET  palette at start-up

The RGB colours of the 16 C64 colours, as the Ultimate shows them. Files are 48 bytes (red, green, blue per colour, in C64 colour order); with VPL a VICE palette file. BBC gives the 8 C64 colours the BBC colours use the BBC's pure red, green, ... The start-up palette is the one chosen in the Ultimate's menu.

VDU 19,l,16,r,g,b sets logical colour l to an RGB colour (0-255 each): in Upic Lite modes that colour only, elsewhere the C64 colour l shows.

Needs firmware 3.15a or later; all but C64 need an REU. Upic Lite and MODE 7 use the palette for their own picture and keep it until the next MODE change.

@@ *SID | SID
  *SID               list the SIDs
  *SID PAN <unit> <p>     stereo
  *SID VOL <unit> <dB>    volume
  *SID SETUP              8 SIDs

The SIDs found at start-up: up to 8, at &D400-&D7E0. The cartridge's .cfg sets up 8 UltiSIDs (two UltiSIDs split four ways, as Heartbeat Soundtracker does) and switches them on, UltiSID 1 left and UltiSID 2 right.

*SID SETUP sets up the 8 SIDs as the cartridge's .cfg does (two UltiSIDs split four ways, UltiSID 1 left, UltiSID 2 right) and finds them again. The Ultimate applies the .cfg only when the cartridge is started from its file browser, so BBC BASIC does this at start-up by itself when it finds fewer than 8 SIDs. Lasts until the Ultimate is reset.

unit: 1 or 2 (UltiSID 1 or 2; with the .cfg the 1st, 3rd, 5th and 7th SID are UltiSID 1's) or S1, S2 (the SID sockets). p: -5 (left) to 5 (right), 0 centre. dB: -42 to 6, or OFF; rounded to the Ultimate's steps (-42 -36 -30 -27 -24, then -18 to 6 in single dB). The setting takes effect at once and lasts until the Ultimate is reset. Needs firmware 3.15a.

@@ *SOUND
  *SOUND         show the mode
  *SOUND SID     SID mode (start-up)
  *SOUND BBC     BBC Micro mode
  *SOUND NONE    no engine: more memory
  *SOUND OFF     sound off
  *SOUND ON      sound on again
  *SOUND STOP    silence, queues empty

SID mode: SOUND plays all voices of up to 8 SIDs with instruments (see SOUND, *INSTRUMENT). BBC mode: SOUND and ENVELOPE as on a BBC Micro, channels 0-3. Changing the mode stops all sound; envelopes are kept (with an REU).

NONE takes the sound engine out of memory: &0900-&1CFF is free, and a program may set PAGE=&900 for 31K. SOUND is then ignored. *SOUND SID or BBC brings the engine back, but only while PAGE is &1D00 or above.

@@ *INSTRUMENT | INSTRUMENT
  *INSTRUMENT n         list it
  *INSTRUMENT n parts   change it
  *INSTRUMENT n NAME text
  *INSTRUMENT n COPY m
  *INSTRUMENT DEFAULT
  *INSTRUMENT SAVE <file>
  *INSTRUMENT LOAD <file>

64 instruments for SID mode; 1-16 are ready-made: SQUARE PIANO ORGAN STRINGS BRASS LEAD BASS FLUTE PLUCK BELL KICK SNARE HIHAT PAD ARP SYNC. Needs an REU. Parts:

TRI SAW PULSE NOISE RING SYNC: the waveform (several mix). ADSR a d s r: the envelope (0-15 each). PW w [rate top bottom]: pulse width 0-4095; with a sweep, the width moves by rate (-128 to 127) each interrupt, turning at top and bottom (the width's high part, 0-15).

FILTER [LOW] [BAND] [HIGH] [RES r] [CUT c [rate top bottom]]: through the filter; c the cutoff (0-255), a sweep as for PW (top, bottom 0-255); STOP: the sweep stops at its end, BOUNCE: it turns. NOFILTER.

VIB delay width rate: vibrato after delay interrupts, width in 1/8 semitones, rate 1-63. PORTA speed: slides to each new note (speed/64 semitone per interrupt). FINE f: tuning in 1/64 semitones (-128 to 127). RESTART / NORESTART: hard restart (a clean new attack).

WAVES w ...: up to 16 waveform steps (255 n: go on at step n; 0: end); ARP a ...: semitone offsets for the same steps (chords, drums); SPEED n: interrupts per step.

  *INSTRUMENT 20 COPY 2 SAW
  *INSTRUMENT 20 ADSR 0 8 0 9
  *INSTRUMENT 21 PULSE PW 800 6 14 2
  *INSTRUMENT 21 VIB 20 2 6
  *INSTRUMENT 22 WAVES 65 65 255 0
  *INSTRUMENT 22 ARP 0 4 7 SPEED 2

@@ *SONG | SONG | TRACKER
  *SONG                show it
  *SONG NEW [bpm [rpb]]
  *SONG RECORD [OFF]
  *SONG PLAY [position]
  *SONG STOP
  *SONG TEMPO bpm
  *SONG TITLE text
  *SONG COMPOSER text
  *SONG SAVE <file>
  *SONG LOAD <file>

A song of up to 24 voices kept in the REU, played in the background by the SID engine (*SOUND SID), in every screen mode. Build it from BASIC: after *SONG RECORD, SOUND writes notes into the song instead of playing them; the duration counts in rows (a beat has rpb rows, default 4; tempo bpm, default 120). Each voice keeps its own place, so voices can be written one after another. *SONG RECORD OFF ends the song after the furthest note.

  *SONG NEW 100
  *SONG RECORD
  SOUND 0,4,53,4:SOUND 0,4,61,4
  SOUND 1,7,25,8
  *SONG RECORD OFF
  *SONG PLAY

Pitch as SOUND, rounded to semitones; amplitude 1-64 an instrument, -15 to -1 the voice's instrument at that level, 0 a rest. Up to 28 patterns of 64 rows (1792 rows). ADVAL(-29-v) gives the note voice v plays (49 = middle C), to draw meters while it plays.

@@ *SPRITE | SPRITE | SPRITES
  *SPRITE ON | OFF    the multiplexer
  *SPRITE n ON x,y    show sprite n
  *SPRITE n OFF       hide it
  *SPRITE n SHAPE s   its shape (0-63)
  *SPRITE n COLOUR c  its colour
  *SPRITE n SIZE w,h  1 or 2 each way
  *SPRITE n MULTI ON  multicolour (OFF)
  *SPRITE n BEHIND    behind graphics
  *SPRITE n FRONT     in front of them
  *SPRITE COLOURS a,b the shared pair
  *SPRITE DEFINE s h  shape: 126 hex
  *SPRITE LOAD s file shapes from s on
  *SPRITE             the sprites shown

Up to 32 sprites (0-31) of 24 x 21 dots on the VIC-II's 8, reused down the screen by a raster interrupt (at most 8 on one line: a 9th drops out where 9 meet). *SPRITE ON loads that multiplexer below HIMEM and lowers HIMEM by 1.25K (at the prompt at once, in a program with the next MODE: put it before MODE); *SPRITE OFF gives the memory back, as *SOUND NONE does for sound. A MODE hides all sprites.

x,y are BBC graphics coordinates (0-1279, 0-1023), of the sprite's bottom left corner; colours are BBC colours 0-15. Shapes: 3 bytes a row of 24 dots, 21 rows (as SpritePad), kept in the REU:

  *SPRITE ON
  *SPRITE DEFINE 0 FFFFFF...
  *SPRITE 0 ON 640,512

*SPRITE LOAD reads SpritePad files (SPD version 1), files with a 3-byte header, or plain 64-byte shapes. Multicolour sprites have 12 x 21 double-wide dots in 4 colours: transparent, the sprite's own, and the pair *SPRITE COLOURS sets for all sprites (the VIC-II has one pair).

In the graphics modes and MODE 7 the bitmap leaves room for two shapes: the multiplexer copies each sprite's shape in as it comes, so sprites on the same lines can have at most 2 different shapes (the text screen holds all 64).

OSWORD &71 does it from programs without command parsing: block +0 sprite, +1 action (0 hide, 1 show at +2/+3 x, +4/+5 y, 2 shape +6, 3 colour +6, 4 collisions into +6: bit 0 another sprite, bit 1 the picture, cleared when read).

Upic Lite cannot show VIC-II sprites: use MODE 128+n there. Needs an REU.

@@ *UPIC | UPIC
  *UPIC SHOW [n]    show the picture
  *UPIC LOAD file   a Upic file
  *UPIC SAVE file   the picture
  *UPIC CLEAR [c]   new, colour c
  *UPIC AUTO ON|OFF automatic shows

Upic (Aleksi Eeben): 384 x 256 pixels in 16 colours, every pixel its own colour, drawn by the CPU at 48 or 64 MHz. The picture is kept in the REU (&90000) and shown on request: SHOW moves BASIC's memory aside, shows the picture until a key is pressed, and puts everything back (the program goes on where it was; TIME counts on). On a 48 MHz Ultimate 3 of every 4 pixels show.

LOAD reads Upic v1.3 files (as Upic Paint and the Upic Image Converter save them, with their palette) or a bare 49152-byte picture; SAVE writes v1.3. CLEAR starts a new picture in colour c with the C64 palette.

  *UPIC LOAD harbour.upic
  *UPIC SHOW

SHOW n shows it for n centiseconds at most (a key ends it earlier): progress views while a program draws.

MODE 110 and 111 draw into this picture: graphics there, text on a 40x25 console; colours are the mode's logical colours (as MODE 2), VDU 19 changes them (VDU 19,l,16,r,g,b any RGB). When the picture has changed it is shown by itself: when a program ends (until a key), in GET (the key is GET's) and in INKEY of half a second or more (at most that long). AUTO OFF leaves only SHOW.

Needs an REU of 1 MB; SHOW needs a 48 or 64 MHz Ultimate.

@@ *SGET | SGET | *SCHOOSE | SCHOOSE | *SDELETE | SDELETE | *SNEW | SNEW | *SRENUMBER | SRENUMBER | *SLOAD | SLOAD | *SMERGE | SMERGE | *SSAVE | SSAVE | *SSPACE | SSPACE | *SMASK | SMASK | GXR

@@ *SRWRITE | SRWRITE

Pattern fill (ECF, as on the BBC Master): action + 16 * n uses pattern n (1-4) instead of the colour, for everything drawn. VDU 23,12+n-1,c1,...,c8 defines pattern n as 2x4 pixels of logical colours (row by row); VDU 23,11,0;0;0;0; restores the default patterns. VDU 23,2-5 (GXR and Master) define pattern 1-4 as eight screen bytes in the BBC layout of the mode; the first two pixels of the first four bytes are used. VDU 23,6 (the dot-dash line pattern) and *FX 163,242 are accepted; dotted lines plot every second pixel.

  GCOL 0,1:DRAW 1279,1023
  GCOL 16,0:PLOT 157,640,512

@@ MODE
  MODE n

Selects a screen mode and clears it.

  MODE size     col text  U64
  0    320x200  2   80x32 VIC-II
  1    320x256  4   40x32 Upic Lite
  2    160x256  16  20x32 Upic Lite
  3    text     2   80x25 VIC-II
  4    320x256  2   40x32 Upic Lite
  5    160x256  4   20x32 Upic Lite
  6    text         40x25 Upic Lite
  7    teletext     40x25 VIC-II
  100  C64 text     40x25
  103  320x200  16  40x25 hires
  104  160x200  16  20x25 multicol.
  110  384x256  16  40x25 Upic full
  111  288x256  16  40x25 Upic 48 MHz

MODE 7 is teletext, as on the BBC: screen memory at &7C00 (HIMEM &7C00), colour codes 129-135 (text) and 145-151 (mosaic graphics), 141 double height, 154 separated graphics, 157 new background, 156 black background, 158 hold graphics, 136 flashing. Writing to &7C00 directly (?&7C00=...) shows within a few frames. The machine starts in the C64 text screen; MODE 100 returns to it.

MODE 0 and MODE 3 have 80 columns in a 4x6 font (X11 misc-fixed, public domain), each character 4 pixels wide: MODE 0 with graphics as MODE 4 (rows of 6 lines), MODE 3 text in rows of 8. They stay on the VIC-II (HIMEM &8000): Upic Lite blurs such thin letters. *HELP texts stay 40 wide; *CAT uses the width. MODE 1 on the VIC-II (MODE 129, *SHADOW) uses the same font for its 40 columns: its 160 double-wide pixels leave 4 per character. MODE 6 uses rows of 10 lines (250 lines), as on the BBC; without Upic Lite they are the 40x25 text screen. MODE 103: 2 colours per 8x8 cell, MODE 104: 4 per 4x8 cell, as the VIC-II does.

Upic Lite: a live picture of 320x256 (MODE 2 and 5: 160x256 with double-width pixels, 16 or 4 colours anywhere) with square pixels, as on the BBC, on 64 MHz machines (Ultimate 64 Elite II, C64 Ultimate) with firmware 3.15+. The screen memory lies below HIMEM as on the BBC (MODE 4, 5, 6: &5800; MODE 1 and 2: &3000), and BASIC runs at about 1/6 of its speed while the picture is shown. Elsewhere these modes use the VIC-II (200 lines, 32 rows of 6-line text).

Upic full (MODE 110, 111): graphics go into a 16-colour picture in the REU (OS units 1536 x 1024 in both: 4 per pixel in 110, 16/3 in 111, so circles stay round), text to a 40x25 console on the screen; the picture shows with *UPIC SHOW (see UPIC). MODE 111 has 288 pixels: 3 of every 4 that a 48 MHz Ultimate shows; MODE 110 needs 64 MHz. HIMEM stays &8000.

@@ PLOT
  PLOT k,x,y

Graphics plotting, as on the BBC: k AND 3 = 0 moves, 1 draws in the graphics colour, 2 inverts, 3 draws in the background colour; k AND 4 = 0: x,y relative to the graphics cursor.

  k 0-7     line
  k 8-15    line, no end point
  k 16-31   dotted line
  k 32-63   line, no start point
  k 64-71   point
  k 72-79   line fill left/right (GXR)
  k 80-87   filled triangle
  k 88-95   line fill right (GXR)
  k 96-103  filled rectangle
  k 112-119 filled parallelogram
  k 128-135 flood fill (background)
  k 136-143 flood fill to foreground
  k 144-151 circle
  k 152-159 filled circle
  k 160-167 arc
  k 168-175 segment
  k 176-183 sector
  k 184-191 block move/copy (GXR)
  k 192-199 ellipse
  k 200-207 filled ellipse
  k 216-223 rectangle (U64)
  k 224-231 triangle (U64)
  k 232-239 sprite (GXR, see SGET)
  k 240-247 parallelogram (U64)

Triangles use the last three points; a rectangle's corners are the previous point and x,y; a parallelogram's fourth corner is worked out as on the BBC. Circles: the centre is the previous point, x,y a point on the circle (PLOT 153,r,0 after MOVE cx,cy). Ellipses: centre, then a point at the end of the horizontal axis, then x,y gives the height. The (U64) outline codes are extensions; the BBC has no outline triangle, rectangle or parallelogram. Flood fill 128-135 fills the background-coloured area around x,y; 136-143 fills up to the foreground colour. Arcs, segments and sectors: the centre is the point two plots back, the previous point gives the radius and the start, x,y the end direction; drawn anticlockwise.

Line fills (as the GXR and the Master): 72-79 fills the row at x,y left and right over background-coloured pixels; 88-95 fills to the right over pixels that are not the background colour. Block move/copy: the rectangle between the last two points goes with its bottom left corner to x,y; 185/189 move it (background left behind), 186/190 copy it. Overlapping rectangles are handled.

  MOVE 0,0:MOVE 99,99:PLOT 190,400,0

@@ SOUND
  SOUND c,a,p,d

Queues a note, as on a BBC Micro. c = &HSFN: N channel (0 noise, 1-3 tone), F=1 flush the queue first, S sync with S other channels (they start together), H=1 hold (the previous note's release goes on). a: -15 (loud) to 0, or envelope 1-16. p: pitch, 4 steps per semitone, 53 = middle C, 89 = A 440 Hz; channel 0: 0-2 periodic noise, 4-6 white noise (high to low), 3 and 7 at channel 1's pitch. d: 1/20 s, 255 or -1 for ever.

This is BBC mode (*SOUND BBC): channels 1-3 on SID 1, channel 0 on the second SID (or with one SID, on channel 3's voice while it plays).

SID mode (the start-up mode): c = &FSVV: VV voice 0-23 (voice v MOD 3 of SID v DIV 3), S sync with S other voices (0-15), F: 1 flush, 2 hold, 4 tie (new pitch, no new attack). a: instrument 1-64; instrument + 256 * loudness (1-15, scales the instrument's own sustain: &0A08 is instrument 8 at 10/15; drums stay drums); -15..-1 the voice's instrument at that loudness; 0 a rest. p: as BBC mode, also below 0 for low notes.

Three notes wait per voice; see ADVAL.
